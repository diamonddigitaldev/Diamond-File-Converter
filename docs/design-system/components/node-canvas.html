Dragging

Pointer events with capture, not mousedown on the document. setPointerCapture on the node, deltas measured from the pointer's origin against getBoundingClientRect(), and both listeners removed on pointerup. The same idiom as any other drag handle in the house.

Do not measure the DOM to draw edges. Port positions are computed from the node's stored coordinates and its index in the port list. Measuring means a layout pass per frame, and it breaks entirely while a node is mid-transition.

Repaint the edges, not the graph. While a node is being dragged, move its element and redraw the edge layer only. Rebuild the whole canvas once, on release.

Refusing a connection

Light only what would work. While a link is being dragged, every input port is tested and marked candidate or blocked. The user should not have to drop it to find out.

The editor enforces what the model tolerates. A permissive data model is right — it has to load whatever is on disk — but the editor is where a bad edge is prevented. Type mismatch, an input that is already connected, an output fanned into two nodes, a self-connection, a loop. Each gets its own sentence, not a generic "invalid".

Say the reason, in the app's words. "An output can only feed one node." beats surfacing whatever the underlying tool would eventually have said, and beats a graph that validates cleanly and then fails at run time.

Around the canvas

A three-column layout: the saved list on the left, the canvas in the middle, an inspector on the right, and a validation strip with a live compiled preview beneath. The canvas is what needs the room — keep the side panels as narrow as their content allows, and let collapsing the nav rail be the user's lever for more.

Drive the inspector from a schema, not a hand-written form per node type. Each node type declares its parameters — label, type, unit, bounds, options, help — and one function renders any of them. A second hand-maintained table of the same facts drifts from the first.
