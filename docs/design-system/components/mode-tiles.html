Why a shadow as well as a border. Growing the border to 3px on selection would change the box size and shift everything beside it. A 1px shadow in the same colour sits outside the border and reads as a thicker edge with no reflow.

Behaviour

One source of truth. A click sets a single state variable, then every tile recomputes its own selected class from it. Do not toggle tiles against each other.

Strictly one or the other. Re-clicking the active tile does nothing. Craftbox's create-server source tiles are tri-state — clicking the selected one deselects back to "from scratch" — but that only works because it has a meaningful third state. Where there are exactly two modes, deselection would leave the form in no mode at all.

Fail closed, then unlock. A tile with nothing behind it ships locked and is enabled at runtime once its data exists — Craftbox locks Template until a template is saved; File Converter locks Pipeline until a pipeline is saved. Enforce it in the handler as well as the CSS: pointer-events:none stops a mouse but not a keyboard or a programmatic activation.

Keyboard operable. role="button", tabindex="0" (-1 when locked), aria-pressed, and Enter/Space activation, with a :focus-visible ring. The original pattern has only role="button" and cannot be reached from the keyboard at all — do not copy that part.

Dependent sections

The chooser swaps which controls appear below it, by toggling d-none. Both branches stay in the DOM. Values in the hidden branch are kept, not cleared, so switching back and forth is lossless — but only the active branch is read when the work runs, and the card shows only the active branch.
